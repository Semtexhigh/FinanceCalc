what the .dmg contains

Eight layers, one 5 MB file

The app you see is the same single HTML file it always was. Everything below it is new: a Rust process that owns the window, the filesystem and the update channel.

0builds shipped
0rust commands
0ownership markers
0network calls

Rust application shell

Tauri 2 · universal binary

The window, the menu and the process are Rust. The web view is a passenger inside it, with no title bar of its own — the header you drag is the app's own chrome.

  • aarch64 + x86_64 in one binary
  • macOS 11 Big Sur and later
  • symbols stripped from the release build

Native folder bridge

10 commands · src/folder.rs

The reason the desktop build exists. Ten Rust commands give the app real file access, which the web view can never have on its own.

  • native folder picker, remembered between launches
  • write to a temp file, then rename — never a half-written save
  • path traversal refused at the boundary
  • dotfiles skipped, so iCloud placeholders stay invisible

iCloud Drive & OneDrive

your folder, their sync

Point it at a folder inside iCloud Drive or OneDrive and the sync client does the rest. The app writes plain files; nothing is uploaded by the app itself.

  • one JSON file for the ledger
  • receipt photos as ordinary image files beside it
  • open the same folder on another Mac and carry on

Five-tier storage ladder

folder → OPFS → IndexedDB → local

The folder is tier zero. If it is missing the app falls down the ladder rather than losing anything, and tells you which rung it is standing on.

  • conflict detection against a newer copy from another device
  • your version kept in history before anything is overwritten
  • a health read-out per tier, with free space

Mangled frontend

terser compress + mangle

Every name in the shipped script is rewritten before the app is bundled. The build refuses to produce a .dmg if the mangler is missing or the output looks wrong.

  • one IIFE, no inline handlers, no eval to break
  • build fails rather than shipping readable source

Provenance layer

256 markers · PROVENANCE.json

Two hundred and fifty-six unique ownership markers are compiled into the binary and touched at startup so the optimiser cannot discard them.

  • author, build number and repository in every marker
  • SHA-256 of each shipping file, published with the release

Signed update channel

Ed25519 · minisign

The public key is compiled into the app. It will only install an update whose signature matches — so the channel cannot be hijacked even though the .dmg is unsigned.

  • manifest checked at launch
  • a bad signature is simply refused

Offline by construction

no account · no telemetry

There is nothing to sign in to and nowhere for the data to go. The only outbound request the app can make is the update check, and you can leave that alone.

  • no analytics, no crash reporting, no identifiers
  • works with the network switched off
